## 用語（2026-11-05）
<a id="terms"></a>

似た言葉が、別の層の別のものを指すことがある。とくに「センス」と「ステータス」は 2 つずつある。

| 用語 | 層 | 意味 | 仕様書の場所 |
|---|---|---|---|
| センス（BIOS） | OS ↔ BIOS | INT 1Bh の機能 AH = 04h。ドライブの種類（容量の種類）を AH で返す。ジオメトリは返さない | 6.3 の 4h、3.2 の +14h |
| 新センス | OS ↔ BIOS | INT 1Bh の機能 AH = 84h。AH（種類）、BX = セクタ長、CX = シリンダ数 − 1、DH = ヘッド数、DL = セクタ数を返す。対応していることを 0000:0480h の bit7 で示す | 6.3 の 4h、2.6、3.2 の +03h、+04h、+1Ch |
| REQUEST SENSE（03h） | BIOS ↔ ターゲット | 直前の命令の誤りの中身を、ターゲットから読む命令 | 2.5 |
| 4 バイトのセンス（SASI のセンス） | BIOS ↔ ターゲット | REQUEST SENSE が返す SASI の形のデータ（バイト 0 = エラーコード、バイト 1〜3 = アドレス）。UX-31 のコントローラが返す形。BIOS は 4.5 の表で INT 1Bh の AH に読み替える | 2.5、4.5 |
| 拡張センス（18 バイト） | BIOS ↔ ターゲット | REQUEST SENSE が返す SCSI の形のデータ（エラーコード 70h。センスキー、ASC など）。10 バイト型のターゲットから読む。新センスとは関係ない | 付録 C |
| ステータス（82h） | BIOS ↔ ホストアダプタ | I/O 82h の読み出し。NRDSW = 1 で SASI バスの状態、0 でドライブの種類（容量コードとセクタ長） | 2.1 |
| 状態バイト（ステータスフェーズ） | BIOS ↔ ターゲット | 命令の終わりにターゲットが送る 1 バイト（00h = 正常、02h = エラー + LUN × 20h など） | 2.4 |
| 容量コード | ホストアダプタ | 82h（NRDSW = 0）で読む 3 ビット（ユニットごと）。111b は未接続 | 2.1、3.1 |
| 厚型 / 薄型 | BIOS | 容量コード 100b（20 MB）の 2 つのジオメトリ。INT 1Bh の 0Eh / 8Eh で選ぶ | 3.1、3.4 |
| パラメータ表 | BIOS | 容量コードごとの 30 バイトの表。05E8h / 05ECh のポインタが指す | 3.2 |
| 組 A / 組 B | BIOS → ターゲット | パラメータ表の中の、C2h のデータ（10 バイト）の形をした 2 つの組。A はふだん、B はリキャリブレートとリトラクト。表から送るのはバイト 0〜7 で、バイト 8〜9 は BIOS がセクタ長と 00h にする | 3.2、4.4 |

## 1. 範囲

**手本にする BIOS（0.15 版、2026-11-01、ユーザーの決定）**
- この BIOS は、UX21 の拡張 ROM の SASI BIOS に合わせる必要はない。古い版と新しい版で振る舞いが違うところは、より新しい設計
  （DX2 などの内蔵 SASI BIOS。ES2 の版を改訂したもの）の振る舞いを使う。例: DMA のチャネルを 0000:0484h で選ぶ（2.3）。
- ただし、次のものは新しい設計にあっても採らない。
  - 相手のベンダー名を確かめて止まること（4.3 の INQUIRY）。この BIOS は NEC 以外のターゲット（SASI エミュレータ、変換番長、SCSI のディスク）ともつなぐため。
  - 古い機種（PC-9801-27 の 17h / 19h 版の時代）にしかない振る舞い、フロッピーの拡張 BIOS。
- 版どうしで同じところ（表、手順、システム共通域の使い方）は、どの版を手本にしても同じなので、この文書の本文のとおりにする。

### 1.1 対象機種と前提

- **対象機種は、次の 3 つを満たす機種**（2026-11-01、ユーザーの決定。機種の例は付録 E）。
  1. CPU が V30 以上。命令は V30 にある範囲（80186 の命令まで。PUSH の即値、シフトの回数の即値、PUSHA / POPA など）で書く。
     80286 以降の命令は使わない（UX は V30 モードでも動く）。**8086 の機種（PC-9801 初代、E、F、M）は、CPU を V30 に載せ替えても対象外**（2026-11-05、ユーザー）。
     これらの機種の拡張 ROM の番地（D6000h / D7000h のどちらに置くか、ほかのボードの ROM との重なり）は考えない。
  2. **本体に内蔵 IDE がない**（内蔵 IDE BIOS を持たない）。内蔵 IDE の機種では IDE BIOS が DA/UA 80h、81h を受け持ち、SASI と同時には使えない
     （UNDOCUMENTED 9801/9821 のSASI の項、IDE の項[[1]](#ref-1)）。drachen6jp 氏の分類の第 0 世代（PC-9801UR、US、NS など。
     容量決め打ちの内蔵 IDE）以降の内蔵 IDE の機種は、すべて対象外。
     内蔵 IDE の機種でも、IDE の HDD を付けなければ IDE BIOS は出ず、PC-9801-27 を使える（同じ資料）。この使い方は対象に含めない（試さず、動作を保証しない）。
  3. PC-9801 のノーマルモードで、拡張 ROM の初期化 1〜3 とブートの呼び出しを行う。
  - 手元で ROM を調べたのは UX21、ES2、DX2（どれも対象機種）と BX4（内蔵 IDE の機種。拡張 ROM の呼び出し方を調べるためだけに使った）。
- SASI のインターフェースは本体内蔵か PC-9801-27 と同じ I/O（80h、82h）、割り込み IR9、DMA チャネル 0（専用スロットの内蔵ユニットでは 0〜3 のどれか。2.3）。
- 扱う固定ディスクは 2 台（DA/UA = 80h、81h）。コントローラは SASI のターゲット ID 0 の 1 台。1 台のときは ID 0 の LUN 0（80h）、2 台のときは ID 0 の LUN 0（80h）と LUN 1（81h）。
  付録 C を入れたときだけ、81h の宛先が ID 1 の LUN 0 になることがある（付録 C の 5）。
  4 台に広げる案（付録 A）は不採用（2026-10-29）。
- DA/UA は 80h、81h（CHS 指定）と 00h、01h（リニア指定）の両方を受ける（6.2）。MS-DOS はリニア指定（00h、01h）で読み書きする。
- ハイレゾモード、フロッピーの拡張 BIOS（PC-9801-27 や UX21 の ROM に同居しているもの）、PC-9801 初代用の入口（オフセット 0000h）は扱わない。0000h〜0008h は 3 バイトごとに RETF（CBh）と NOP（90h）2 個を置く。

### 1.2 置き場所

- 拡張 ROM として D0000h〜DFFFFh の 4 KB 境界に置く。ノーマルモードの SASI BIOS の通常の置き場は D7000h。
- 同じ中身が 2 か所以上に見えても正しく動く（UX21 の実機で、基板の接触不良により拡張 ROM の 4 KB が D5000h と D7000h の両方に見えた例がある[[154]](#ref-154)）。
  先に初期化 1 で呼ばれた写しだけが持ち主になり（4.2）、ほかの写しは初期化 2 とブートで何もしない（4.3、5）。
- 大きさは 4 KB 以内を目標にする（元の BIOS は 4 KB に収まっている[[46]](#ref-46)[[45]](#ref-45)。UX21 の拡張 ROM の 4 KB の枠に入れる場合は必須）。
- 本体 ROM の一部を差し替える使い方では、同じ ROM の中のほかの部分（UX21 ではフロッピーの拡張 BIOS とサウンド BIOS）を
  壊さない。配るのは差分だけ（NEC の ROM は配らない）。
- **PC-9801-27 と同時には使わない**（2026-11-05、ユーザー）。-27 を挿すときは、この BIOS の ROM と、SASI のホストアダプタ（SASIHBA など）を外すか無効にする。
  - -27 は I/O 80h、82h を使うホストアダプタそのもので、ほかのホストアダプタと同時には挿せない。-27 の ROM は対象機種では D7000h に出るので、この BIOS を D7000h に置いていればぶつかる。
  - UX では、ジャンパ SW7 を 6-3 にすると（または P2 のユニットを外して SASI_CONFIG# を H にすると）、拡張 ROM の窓（D7000h）が閉じ、この BIOS も出なくなる。これは外すのと同じに扱ってよい。
  - DIP SW 2-6（内蔵固定ディスクの切り離し）では足りない。ROM は出たままで、初期化 1 の登録も行い、初期化 2 でドライブがないとするだけ（4.3 の手順 6）。
- 4 KB の全バイトの和（下位 8 ビット）が 00h になるように、最後のバイト（0FFFh）で合わせる。0FFEh は何でもよい（0 でよい。Q23）（元の BIOS がそうなっている[[46]](#ref-46)）。
  UX21 の本体は拡張 ROM の 55h AAh を見るだけで和は確かめない[[87]](#ref-87)が、ほかの機種やソフトのために合わせておく。

### 2.1 I/O ポート

### 2.2 割り込み

- SASI の割り込みはスレーブの 8259 の IR1（システムの IR9）で、ベクタは INT 11h（0000:0044h）。
- 割り込み（INT9）は、INTE = 1 のときステータスフェーズの REQ で立ち、INTE を落とすと消える（テクニカルデータブック 1986 の第 4 部 463 ページ[[52]](#ref-52)）。
- マスクはスレーブの 8259 の I/O 0Ah の bit1（0 = 許可）。終わりの通知（EOI）はスレーブ（I/O 08h）とマスタ（I/O 00h）の両方に出す。
- 割り込みハンドラ（元の BIOS の振る舞い[[46]](#ref-46)[[45]](#ref-45)[[58]](#ref-58)）:
  1. スレーブの 8259 に非特定の EOI（I/O 08h に 20h）を出す。スレーブの ISR（I/O 08h に 0Bh を書いて読む）が 0 なら、マスタにも EOI（I/O 00h に 20h）を出す。
  2. 82h（NRDSW = 1）を読み、次のどちらかなら完了とみなす。そうでなければ何もせず IRET する。
     - ステータスフェーズ: REQ、BSY、CXD、IXO、INT が 1、ACK と MSG が 0（bit1 は見ない）。
     - データフェーズの REQ: REQ、BSY、INT が 1、ACK、MSG、CXD が 0（IXO と bit1 は見ない）。
  3. 完了なら、0000:055Fh の **bit0** を立て（ユニットに関係なく bit0。bit1 は使わない）、82h に C0h（CHEN、NRDSW。INTE と DMAE を落とす）を書いて割り込みを止める。
- 待つ側は、コマンドを送る前に 0000:055Fh の bit0 を 0 にしておき、bit0 が立つのを待ち、立ったら落としてからステータスを読む（Q26）。
- データフェーズの REQ で完了とみなすのは、INTE = 1、DMAE = 0 で命令を出したときにだけ起きる（回路の作り）。この BIOS はその組み合わせを使わないので、
  ふつうは起きない。6.4 の手順 3 の「BX がセクタ長より小さい」呼び出しでは、DMA が先に終わってターゲットが次のデータを求めたまま止まり、
  完了待ちかステータスの待ちが時間切れ（AH = 90h）になる。呼び出し側の誤りなので、それでよい（Q26）。
- 割り込みハンドラで I/O 08h に書いた 0Bh（ISR を読む形）は、元に戻さない（Q31）。
- IF: 本体の INT 1Bh ハンドラは STI してからこの BIOS を呼ぶ。初期化 2 では、ベクタを置いたあと STI してよい（完了待ちに割り込みが要る）。
  マスタの 8259 のマスク（カスケードの IR7）には触らない（本体が許可している前提）（Q6）。

### 2.3 DMA
根拠: テクニカルデータブック[[3]](#ref-3)、Undocumented 9801/9821[[1]](#ref-1)、NEC の SASI BIOS の解析[[46]](#ref-46)[[45]](#ref-45)[[58]](#ref-58)。

- **使うチャネル c**（0.14 版、付録 B）: DMA を設定するたびに 0000:0484h を読み、bit4 が 1 なら c = bit7〜6（0〜3）、bit4 が 0 なら c = 0。
  0484h は本体が起動時に作る値で、この BIOS は書き換えない。
- PC-98 の 8237 の I/O は、チャネルごとにアドレス 01h / 05h / 09h / 0Dh、カウント 03h / 07h / 0Bh / 0Fh、ページ 27h / 21h / 23h / 25h（c = 0 / 1 / 2 / 3）。
  シングルマスク 15h、モード 17h、バイトポインタのクリア 19h は共通。
- モードの値: 読み出し（I/O → メモリ）= 44h + c、書き込み（メモリ → I/O）= 48h + c、ベリファイ（転送しない）= 40h + c。いずれもシングル転送。
- マスクを外すのは 15h に c、掛けるのは 15h に 04h + c（c = 0 なら 00h と 04h）。ほかのチャネルのマスクには触らない。
- カウントには「バイト数 − 1」を書く。
- 転送する範囲が 64 KB の境界をまたぐ（物理アドレスの下位 16 ビット + バイト数 − 1 が FFFFh を超える）なら、コマンドを出さずに AH = 20h で返す。
- 終わったら（エラーでも）チャネル c をマスクする（15h に 04h + c）。

### 2.4 SASI バスの手順（ホスト側）
根拠: テクニカルデータブック[[52]](#ref-52)[[3]](#ref-3)、SASI の規格[[66]](#ref-66)、NEC の SASI BIOS の解析[[46]](#ref-46)[[45]](#ref-45)[[58]](#ref-58)、UX-31 のコントローラのファームウェアの解析[[153]](#ref-153)。

待ちはすべて時間切れを持つ（4.6）。時間切れなら AH = 90h で終える。

**ACK# は回路が出す**: ホストのソフトは ACK# を操作しない（82h に ACK のビットはない）。80h の読み書き、または DMA の 1 サイクルが終わると、インターフェースの回路が ACK# を出し、ターゲットが REQ# を落とすと回路が ACK# を落とす（UX-31 の回路でも同じ[[155]](#ref-155)）（テクニカルデータブック 1986 の第 4 部 460 ページ[[52]](#ref-52)「ACK は IDR をリードしたとき、または ODR にライトしたときハードウェアによりセットされ、REQ 信号がオフになるとリセットされる」。461〜463 ページのタイミングチャートも同じ）。SASI の規格の「ホストが ACK を出す」手順は、ソフトではなく回路が行う。

1. **選択**: BSY が 0 になるのを待つ → 80h にターゲットのビット（ID 0 なら 01h）を書く → 82h に 60h（NRDSW、SEL）を書く →
   BSY が 1 になるのを待つ → 82h に C0h（CHEN、NRDSW。SEL、INTE、DMAE は 0）を書く。
   BSY が 1 にならず時間切れなら、82h に 40h を書いて（SEL を落とす）AH = 90h で終える。
   - 選択のあと、コマンドを送る前に、命令に応じて 82h に次の値を書く: DMA を使う命令（読み出し、書き込み、ベリファイ、0Bh の代替トラックの割り当て）は C3h（CHEN、NRDSW、DMAE、INTE）、完了を割り込みで待つそのほかの命令（TEST UNIT READY、REZERO、SEEK、FORMAT など）は C1h（CHEN、NRDSW、INTE）、PIO でデータを受け渡す命令（REQUEST SENSE、C2h）は C0h のまま。
2. **コマンド**: 6 バイト（C2h では続けてデータ 10 バイト、2.5）を 1 バイトずつ送る。各バイトの前に、REQ = 1、BSY = 1、CXD = 1、
   MSG = 0、IXO = 0 になるのを待ち、80h に書く。書いた後、ACK が 0 であることを確かめてよい（内蔵型は常に 0）。
   - C2h の 10 バイトのデータ: UX-31 のコントローラは、コマンドフェーズのまま（CXD = 1）続けて受け取る[[153]](#ref-153)。データアウトのフェーズ（CXD = 0、IXO = 0）で
     受け取るターゲットにも合うように、各バイトの前は「REQ = 1、BSY = 1、MSG = 0、IXO = 0」を待ち、CXD は問わない。ステータスフェーズに
     進んだら残りを送らない（Q3）。
3. **データ**:
   - DMA を使う命令: 選択の前に DMA を設定しておき、選択のあと 82h に C3h を書いてからコマンドを送る。
   - PIO の命令（REQUEST SENSE など）: 各バイトの前に REQ = 1、BSY = 1 を待ち、データインのフェーズ（CXD = 0、MSG = 0、IXO = 1）なら 80h を読む。
     ほかのフェーズ（ステータスなど）に進んだら、求めたバイト数に足りなくても読むのをやめて手順 5 へ進む（Q30）。
4. **完了待ち**: 82h に INTE を立てた命令（C3h、C1h）は、割り込みハンドラが 0000:055Fh の bit0 を立てるのを待つ（2.2）。元の BIOS はこの待ちに時間切れを持たない（割り込みが来なければ止まる）[[46]](#ref-46)[[45]](#ref-45)[[58]](#ref-58)。
   **この BIOS は時間切れを持つ**（0.12 版。8 章の 8）。長さは 4.6。時間切れなら、DMA のチャネル c にマスクを掛け（2.3 のとおり 15h に 04h + c。DMA を使う命令のとき）、手順 7 のとおり AH = 90h で終える。
5. **ステータス**: REQ = 1、BSY = 1、CXD = 1、IXO = 1、MSG = 0 を待って 80h からステータスバイトを読み、0000:0585h（DISK_STATUS）に置く（Q29）。
   続いて MSG = 1 も立つのを待ってメッセージバイトを読む。最後に BSY = 0 になる（バスフリー）のを待ち、82h に 40h（NRDSW のみ）を書く（Q4）。
   0585h には、最後に読んだステータスバイトを置く（エラーのあとに REQUEST SENSE を出したなら、その REQUEST SENSE のもの。Q7）。
6. **エラーのとき**: ステータスバイトの bit1（Check Condition）を先に見る。1 なら、REQUEST SENSE（03h）を出して 4 バイトを 0000:0586h〜0589h に
   読み、4.5 の表で AH に読み替える。bit1 が 0 で bit0 が 1 なら、センスを取らずに AH = 40h（03h は bit1 の扱い。Q1）。
   - REQUEST SENSE そのものが失敗したとき: 時間切れなら AH = 90h、ステータスがエラー（bit1 か bit0）なら AH = 40h。さらにセンスは取らない（Q2）。
7. **時間切れのとき**（AH = 90h で終えるとき）: 82h に 40h を書く（SEL、INTE、DMAE を落とす）。コントローラのリセットはしない（Q21）。

- コントローラのリセット: 82h に 08h（RST）→ 少し待つ → 00h → 40h。その後 82h（NRDSW = 1）の bit5 が 1 ならコントローラなし。

### 2.5 コントローラの命令
根拠: NEC の SASI BIOS の解析[[46]](#ref-46)[[45]](#ref-45)[[58]](#ref-58)、UX-31 のコントローラのファームウェアの解析[[153]](#ref-153)、SASI の規格[[66]](#ref-66)。

**CDB（6 バイト）**: `[命令] [LUN × 20h + LBA の bit20〜16] [LBA の bit15〜8] [LBA の bit7〜0] [ブロック数] [制御]`

- LUN = ユニット番号（0 か 1）。ブロック数 0 は 256 ブロックを意味する。
- アドレスを持たない命令（TEST UNIT READY、REZERO、REQUEST SENSE、C2h）は、1 バイト目を LUN × 20h、2〜3 バイト目を 0 にする。
  ブロック数の欄は、REQUEST SENSE は 4（付録 C の 10 バイト型では 18）、ほかは 0。SEEK はアドレスを入れ、ブロック数は 0（Q15）。
- 制御: 通常 00h。INT 1Bh の AH の bit5（リトライなし）が 1 なら C0h（コントローラにリトライさせない）。その呼び出しで出す
  6 バイトの命令はすべて（C2h、REQUEST SENSE、リキャリブレートの中の SEEK と REZERO も）同じ値にする（Q28）。

| 命令 | Group | 名前 | 使い方 | 本体内蔵の BIOS から |
|---|---|---|---|---|
| 00h | 0 | TEST UNIT READY | センスと初期化。データなし | 同じ |
| 01h | 0 | REZERO | リキャリブレート | 同じ |
| 03h | 0 | REQUEST SENSE | 4 バイトを読む（PIO）。ブロック数の欄に 4 | 同じ（付録 C の 10 バイト型では 18 バイトの拡張センスを読む: **拡張**） |
| 04h | 0 | FORMAT DRIVE | ドライブ全体のフォーマット。ブロック数の欄にインターリーブ | 同じ |
| 05h | 0 | VERIFY | ベリファイ（6.3 の 1h） | 同じ |
| 06h | 0 | FORMAT TRACK | 1 トラックのフォーマット。ブロック数の欄にインターリーブ | 同じ |
| 08h | 0 | READ | 読み出し（DMA） | 同じ |
| 0Ah | 0 | WRITE | 書き込み（DMA） | 同じ |
| 0Bh | 0 | SEEK | シーク | 同じ |
| 0Eh | 0 | ASSIGN ALTERNATE TRACK | 4 バイトのデータ（代替先のアドレス）を送る | 同じ |
| C2h | 6 | SET DRIVE PARAMETERS | CDB の後に 10 バイトのデータを送る（下記） | 同じ |
| **25h** | 1 | **READ CAPACITY** | 初期化でユニットを見分ける。8 バイト（最終 LBA、ブロック長）を読む（PIO） | **拡張**（付録 C） |
| **28h** | 1 | **READ(10)** | 10 バイト型のユニットの読み出し（DMA） | **拡張**（付録 C） |
| **2Ah** | 1 | **WRITE(10)** | 10 バイト型のユニットの書き込み（DMA） | **拡張**（付録 C） |

- 「本体内蔵の BIOS から」の列: 「同じ」は本体内蔵の SASI BIOS も使う命令、**拡張** はこの BIOS が足したもの（付録 C の任意の拡張。太字の行）。拡張の命令は、10 バイト型のターゲットにだけ出す（6 バイト型のユニットには出さない。初期化の見分けの READ CAPACITY を除く）。
- Group は命令コードの上位 3 ビット（Command Group）。0 は 6 バイトの CDB、1 は 10 バイトの CDB（付録 C の 25h、28h、2Ah）、6 と 7 はベンダー独自（C2h は 6。CDB は 6 バイト）。

**C2h のデータ（10 バイト）**: バイト 0〜7 = 3.2 の表のパラメータの組（8 バイト）、バイト 8 = セクタ長（1 = 512 バイト、0 = 256 バイト）、
バイト 9 = 00h。

- 補足（コントローラ側の調べ[[153]](#ref-153)）: UX-31 のコントローラは、この 10 バイトのうちセクタ長と、ヘッド数 − 1、シリンダの上限を使う。
  セクタ長は C2h でコントローラに設定するもので、ドライブには依らない。コントローラは C2h のヘッド数とセクタ数で LBA を CHS に直す。

**ステータスバイト**: 正常 00h、エラー 02h（bit1）、中断など 03h。これに LUN × 20h が足される（ホストは bit1 と bit0 だけを見る）。
メッセージバイトは 00h。

**REQUEST SENSE の 4 バイト**: バイト 0 = エラーコード（bit7 = 1 ならバイト 1〜3 のアドレスが有効、bit5〜0 が種類）、
バイト 1 = LUN × 20h + LBA の bit20〜16、バイト 2〜3 = LBA の bit15〜0。

### 2.6 システム共通域
根拠: Undocumented 9801/9821[[1]](#ref-1)、テクニカルデータブック[[3]](#ref-3)[[51]](#ref-51)、NEC の SASI BIOS の解析[[46]](#ref-46)[[45]](#ref-45)[[58]](#ref-58)、MS-DOS の IO.SYS の解析[[49]](#ref-49)、NP2kai での試験[[156]](#ref-156)。

| 番地 | 名前 | この BIOS の使い方 |
|---|---|---|
| 0000:0044h | INT 11h のベクタ | 初期化 2 で、自分の割り込みハンドラを置く |
| 0000:0480h bit7 | 新センス対応 | 初期化 1 で SASI を登録したら 1 にする |
| 0000:0481h bit0、bit1 | 512 バイトのドライブの閉鎖 | ユニット 0、1 ごと。1 の間は読み書き、ベリファイ、フォーマットなどを AH = 40h で断る（3.4） |
| 0000:04ACh〜04AFh | XROM_PTR | 本体の INT 1Bh ハンドラが飛び先を置く。ブートの間は退避して使う（5） |
| 0000:04B0h | DISK_XROM（DA = 0xh） | 初期化 1 で自分のセグメントの上位 8 ビットを書く（4.1） |
| 0000:04B8h | DISK_XROM（DA = 8xh） | 同上 |
| 0000:04D0h〜04DFh | 拡張 ROM の ID テーブル | 自分の 4 KB の欄に ID を書く（4.1） |
| 0000:0500h bit0 | 機種（1 = VM 以降） | フロッピー部分を持たないので見ない |
| 0000:0500h bit7 | 機種の種類 | 初期化の TEST UNIT READY の回数を決める（4.3。意味は未確認） |
| 0000:0501h bit7〜6 | CPU の速さの種類 | 見なくてよい（4.6。Q24） |
| 0000:055Dh bit0、bit1 | DISK_EQUIP | ユニット 0、1 があれば 1。初期化で決める |
| 0000:055Fh bit0 | 完了の印 | 割り込みハンドラが立て、待つ側が落とす（2.2）。bit1〜7 は触らない（初期化では bit0、bit1 を 0 にする、4.4） |
| 0000:0584h | DISK_BOOT | ブートしたディスクの DA/UA |
| 0000:0585h | DISK_STATUS | 最後のステータスバイト |
| 0000:0586h〜0589h | センス | 最後の REQUEST SENSE の 4 バイト。元の BIOS は、コマンドを組み立てる場所（0586h = ブロック数、0587h〜0589h = LUN と LBA）としても使う[[46]](#ref-46)。実装はこれに倣ってよい |
| 0000:05E8h、05ECh | パラメータ表の FAR ポインタ | ユニット 0、1 の、いま選んでいる表（3.2）を指す |
| A000:3FF2h | メモリスイッチ SW5 | 読まない（本体がブートの AL に使う） |

- 0000:05E8h、05ECh の指す先の形（表の各欄の並び）をほかのソフトが読むかは未確認（未解決 1）。初版は 3.2 の並び（30 バイト）に合わせる。
- **作業域**: この BIOS は ROM の中にあり、自分の RAM を持たない。書いてよいのは上の表の番地と、呼び出し元のスタックだけ。ほかの番地（0000:0400h〜05FFh の空きに見える所を含む）は使わない。
  ユニットごとに覚えることは、05E8h / 05ECh の FAR ポインタで表す。ポインタは ROM の中の 30 バイトの表を指し、どの表を指すかで、容量の型、
  厚型 / 薄型、10 MB の別の表、付録 C の 10 バイト型と宛先（ID / LUN）を区別する。表の +03h、+04h、+14h、+18h、+1Ch は 3.2 と同じ意味にし、
  3.2 で「そのほか」の欄には、この BIOS が自分の印を置いてよい（Q34。付録 C）。
- **スタック**: INT 1Bh は呼び出し元（MS-DOS のデバイスドライバなど）のスタックで動く。本体の INT 1Bh ハンドラが 9 語を積んだあとに呼ばれる（6.1）。この BIOS が使う量は、本体が積む 9 語の下で **28 バイトまで**にする。INT 1Bh の中で入る IR9 の割り込みハンドラの分（割り込みで積まれる 3 語を含む）も、この 28 バイトに含める（0.8 版。0.7 版の 96 バイト + 16 バイトから下げた）。
  - 理由: MS-DOS の IO.SYS は、DA が 8xh の INT 1Bh を、DOS の中の 384 バイトのスタック（ディスク用）のまま出す[[49]](#ref-49)[[156]](#ref-156)。その上には DOS とデバイスドライバが積んだ分がすでにある。NEC の SASI BIOS はこの中で 28 バイトまでしか使わない[[46]](#ref-46)ので、それに合わせる。
  - 本体が拡張 ROM を呼ぶとき（4.2、4.3、5）も、本体のスタックの空きは限られる（起動中のスタックは 256 バイト）。far call の戻り番地の下で、初期化 1〜3 は **34 バイトまで**、
    ブートは **50 バイトまで**にする（ブートで本体の INT 1Bh を呼ぶときに本体が積む 12 語と、その INT 1Bh の中の分を含む）。
  - 付録 C の 10 バイトの CDB と 18 バイトの拡張センスは、スタックに置けない。CDB は 1 バイトずつ作りながら送り、拡張センスは 0586h〜0589h に置く 4 バイトのほかは読み捨てる（付録 C）。

## 3. ドライブのパラメータ

### 3.1 容量コードとジオメトリ
根拠: Undocumented 9801/9821[[1]](#ref-1)、テクニカルデータブック[[3]](#ref-3)[[51]](#ref-51)、NEC の SASI BIOS の解析[[46]](#ref-46)[[45]](#ref-45)[[58]](#ref-58)。

| 容量コード | 物理ジオメトリ（シリンダ × ヘッド） | CHS の計算に使うヘッド数（厚型 / 薄型） | センス 04h の AH | 新センス 84h の AH | 容量（256 バイト × 33 セクタ） |
|---|---|---|---|---|---|
| 000b | 153 × 4 | 4 / 4 | 00h | 00h | 5.2 MB |
| 001b | 310 × 4 | 4 / 4 | 01h | 01h | 10.5 MB |
| 010b | 310 × 6 | 6 / 6 | 02h | 02h | 15.7 MB |
| 011b | 310 × 8 | 8 / 8 | 03h | 03h | 20.9 MB |
| 100b | 615 × 4 | 8 / 4 | 03h | 03h | 20.8 MB |
| 101b | 615 × 6 | 6 / 6 | 04h | 05h | 31.2 MB |
| 110b | 615 × 8 | 8 / 8 | 05h | 07h | 41.6 MB |
| 111b | 未接続 | — | — | — | — |

- 1 トラックのセクタ数は、セクタ長 256 バイトなら 33、512 バイトなら 17（容量コードに依らない）。セクタ長は 82h（NRDSW = 0）の bit7 / bit6。
- 「厚型」と「薄型」は INT 1Bh の 0Eh / 8Eh（3.4）で選ぶ。違うのは 100b の CHS の計算のヘッド数だけ（厚型は 8 ヘッドとして計算し、
  20 MB を 308 × 8 のように見せる）。

### 3.2 パラメータ表（1 個 30 バイト）
根拠: NEC の SASI BIOS の解析[[46]](#ref-46)[[45]](#ref-45)[[58]](#ref-58)。

各容量コードに 1 個。100b だけ厚型と薄型で別の表。001b には 10 MB の別の表がある（4.3 の手順 4）。
表 1 個は 10 バイトずつの 3 つの塊で、組 A（+00h〜+09h）、組 B（+0Ah〜+13h）、属性（+14h〜+1Dh）。組 A と組 B は、C2h のデータ（10 バイト、2.5）と同じ形。

**組 A と組 B**（同じ形。組 A はふだん使う組、組 B はリキャリブレートとリトラクトのときの組で、シリンダの上限が退避位置まで広い）

| 組のバイト | 組 A | 組 B | 大きさ | 中身 |
|---|---|---|---|---|
| 0 | +00h | +0Ah | 1 | UX-31 のコントローラは読まない[[153]](#ref-153)。表の値のとおりにする |
| 1 | +01h | +0Bh | 1 | UX-31 のコントローラは読まない[[153]](#ref-153)。表の値のとおりにする |

### 3.3 アドレスの計算
根拠: テクニカルデータブック[[51]](#ref-51)[[52]](#ref-52)、NEC の SASI BIOS の解析[[46]](#ref-46)[[45]](#ref-45)[[58]](#ref-58)。

- **リニア指定**（AL の bit7 = 0）: LBA = DL の bit4〜0 × 10000h + CX（21 ビット）。DH は見ない。
- **CHS 指定**（AL の bit7 = 1）: LBA = (CX × H + DH) × S + DL。H は表の +18h、S は 33 か 17（3.1）。32 ビットで計算し、最後に下位 21 ビットを使う（Q10）。
  範囲の検査はしない（範囲外はコントローラがセンス 21h で返す）。
- **シリンダだけのシーク**（6.3 の 7h、Fh、4.3 の手順 5）: LBA = シリンダ × H × S（H、S は上と同じ。厚型の 100b では H = 8）（Q9）。
- セクタ番号 DL は 0 から数える。

### 3.4 512 バイトのドライブの閉鎖と、厚型 / 薄型（INT 1Bh の 0Eh / 8Eh）
根拠: NEC の SASI BIOS の解析[[46]](#ref-46)[[45]](#ref-45)[[58]](#ref-58)。

- 0Eh（AH の bit7 = 0）: そのユニットの表を厚型の側から選び、05E8h / 05ECh に置く。そのユニットのセクタ長が 512 バイトなら
  0000:0481h のビットを 1（閉鎖）にし、256 バイトなら 0 にする。
- 8Eh（AH の bit7 = 1）: 薄型の側から選び、0481h のビットを 0（開放）にする。
- 001b のユニットで、いまのポインタが「10 MB の別の表」（4.3 の手順 5）を指しているときは、0Eh / 8Eh でも表を替えない（0481h は上のとおり）（Q11）。
- 付録 C の 10 バイト型のユニットでは、0Eh / 8Eh は表を替えない。0481h のそのビットは、ブロック長 512 のユニットでは上と同じく 0Eh で 1（閉鎖）、8Eh で 0（開放）にし、
  ブロック長 256 のユニットでは 0 にする（0.11 版。8 章の 7）。
- 閉鎖中のユニットへのシーク（00h）、読み出し、書き込み、ベリファイ、フォーマット、08h、0Bh は、ほかに何もする前に確かめ、何も出さずに AH = 40h を返す（Q27）。
- 意味: 256 バイトのセクタしか知らない古いソフトが 512 バイトのドライブを壊さないための仕組み。512 バイトのドライブを使うソフト
  （MS-DOS、ブート処理）は 8Eh を出してから使う。

## 4. 拡張 ROM としての振る舞い

### 4.1 ヘッダ
根拠: テクニカルデータブック[[3]](#ref-3)、NEC の SASI BIOS の解析[[46]](#ref-46)[[45]](#ref-45)[[58]](#ref-58)、UX21 の本体 ROM の解析[[87]](#ref-87)。

| オフセット | 中身 |
|---|---|
| 0000h、0003h、0006h | RETF（CBh）+ NOP NOP |
| 0009h | 55h AAh |
| 000Bh | ID の下位 6 ビット（29h。ID テーブルには C0h を足した E9h を書く。ID E9h は「VX4・XL 以降の内蔵 SASI」として知られた値） |
| 000Ch | 初期化 1 の入口（3 バイトの JMP） |
| 000Fh | 初期化 2 の入口 |
| 0012h | 初期化 3 の入口（何もしないなら RETF） |
| 0015h | ブートの入口 |
| 0018h | INT 1Bh の入口 |

- 本体は D0000h から 4 KB ごとに、0009h が 55h AAh で ID テーブルの欄が 0 の ROM の 000Ch を FAR CALL する（初期化 1）。
  そのとき DS = 0、BX = ID テーブルのその ROM の欄（0000:04D0h〜）の番地。
- 初期化 2（000Fh）、初期化 3（0012h）、ブート（0015h）は、ID テーブルの欄の bit6 が 1 の ROM だけが、全 ROM について順に呼ばれる。
  順序は「全 ROM の初期化 1」→「全 ROM の初期化 2」→「全 ROM の初期化 3」→ ブート。メモリスイッチ SW5 はブートの直前に本体が読む。
- 本体の入口（初期化 1〜3、ブート）から戻るときに元の値にしておくのは、**DS（呼ばれたときの値。0000h）と 0000:04ACh〜04AFh** だけ（Q48）。
  本体は、呼ぶ前に AX、BX、CX（初期化 1 では ES も）を自分で積んで、戻ったあとに取り出す。戻ったあとは、DS を設定し直さずに 04AEh（次の ROM のセグメント）を進め、
  システム共通域を読む。そのほかのレジスタ（AX、BX、CX、DX、SI、DI、BP、ES）は壊してよい。SS:SP は FAR RET で戻るので、積んだ分を取り除いて戻る。
  - スタックの上限（2.6）の中に収まるなら、使うレジスタを保存して戻ってもよい（初期化 2 は 9 個を保存しても 34 バイトに収まる）。ブートは上限が厳しいので、DS と 04ACh〜04AFh だけを守ればよい。

### 4.2 初期化 1（000Ch）
根拠: NEC の SASI BIOS の解析[[46]](#ref-46)[[45]](#ref-45)[[58]](#ref-58)、Undocumented 9801/9821[[1]](#ref-1)。

1. ID テーブルの自分の欄（[BX]）に E9h を書く。
2. 0000:04B0h が 0 のときだけ: 04B0h と 04B8h に自分のセグメントの上位 8 ビット（D7000h なら D7h）を書き、0000:0480h の bit7 を 1 にする。
   04B0h が 0 でない（別の SASI BIOS が先に登録した）なら、登録しない。
3. 0000:04ACh〜04AFh を壊さない（保存して戻す）。

### 4.3 初期化 2（000Fh）
根拠: NEC の SASI BIOS の解析[[46]](#ref-46)[[45]](#ref-45)[[58]](#ref-58)、UX21 の実機[[154]](#ref-154)。

0000:04B0h が自分のセグメントのとき（自分が持ち主のとき）だけ行う。持ち主でなければ何もせず戻る。

- この節と 4.4 の「INT 1Bh の xxh を出す」「xxh の処理を行う」は、どちらも同じ意味で、INT 1Bh 命令で本体を通しても、自分の中の処理を直接呼んでもよい。
  本体を通すと 0000:04ACh〜04AFh が書き換わるので、初期化 2 の入口で退避し、出口で戻す（Q5）。
- コントローラがないと分かって戻るとき、初期化 1 の登録（04B0h、04B8h、0480h の bit7）は取り消さない。055Dh は 0 のままなので OS は使わず、
  INT 1Bh が来れば時間切れ（90h）で返る（Q32）。

1. コントローラをリセットする（2.4）。コントローラがなければ何もせず戻る。
2. INT 11h のベクタ（0000:0044h）を自分の割り込みハンドラにする。
3. INT 1Bh の AX = 0E00h、0E01h（モード設定、3.4）を出す。スレーブの 8259 の IR1 のマスクを外す（I/O 0Ah の bit1 を 0）。
4. 初期化（INT 1Bh の 03h の処理、4.4）を行う。
5. 容量コードが 001b（10 MB）の 6 バイト型のユニットにだけ、シリンダ 0 へのシーク（INT 1Bh の 00h。AL = 80h / 81h、CX = 0、DX = 0）を出す。AH = 00h で返った（シークがすぐ終わった）
   ドライブは、パラメータ表を「10 MB の別の表」（3.2）に替える。そのあと、そのユニットにだけ INT 1Bh の 0Fh（リトラクト）の処理を行う（Q12）。
6. I/O 31h の bit5 が 0 なら、0000:055Dh の bit0、bit1 を 0 にする（ドライブなしとして扱う。I/O 31h の bit5 は DIP SW 2-6 で、ON（0）が「内蔵固定ディスク切り離し」。テクニカルデータブック HARDWARE 1993 の 6.2[[3]](#ref-3)。UX21 の実機でも確かめた[[154]](#ref-154)）。

- ES2 と DX2 の内蔵 SASI は[[45]](#ref-45)[[58]](#ref-58)、0000:0500h の bit7（[[1]](#ref-1) ホットスタートの印）が 0 のとき、ここでユニット 0 に INQUIRY 相当の 12h 命令を出し、返ったデータの
  オフセット 8〜0Ah が "NEC" でなければ "DISK ERROR" を出して止まる。UX21 の SASI BIOS はこれをしない[[46]](#ref-46)。**この BIOS もしない**
  （0.15 版: 手本は新しい設計だが、NEC 以外のターゲットともつなぐため、この確かめは採らない。1 章の「手本」）。

### 4.4 初期化（INT 1Bh の 03h）
根拠: NEC の SASI BIOS の解析[[46]](#ref-46)[[45]](#ref-45)[[58]](#ref-58)。

1. 0000:055Dh と 055Fh の bit0、bit1 を 0 にする。
2. コントローラをリセットする。コントローラがなければ AH = 00h で終わる。
3. 82h（NRDSW = 0）の容量コードが 111b でないユニットについて: パラメータ設定（C2h、**組 B**）を 1 回出し、TEST UNIT READY を、
   成功するまで繰り返す。回数は TEST UNIT READY を出す回数の合計で、0000:0500h の bit7 が 1 なら 2 回、0 なら 30 回。間に 4.6 の待ちを入れる。
   C2h の結果は、時間切れ（90h）のときだけ見て、そのユニットをあきらめる（ほかのエラーは見ずに TEST UNIT READY へ進む）（Q16）。
   成功したら 055Dh のそのユニットのビットを 1 にする。時間切れ（90h）が返ったら、そのユニットはそこであきらめる。
   付録 C を入れるときは、この手順 3 の前に付録 C の見分け方を行い、6 バイト型と分かったユニットにだけ手順 3 を行う（Q35）。
   見分けと手順 3 の順序は、ユニットをまたいでは問わない（全部のユニットを見分けてから手順 3 を行っても、ユニットごとに見分けと手順 3 を続けて行ってもよい。Q46）。
4. 両方のユニットに、パラメータ設定（組 B）、INT 1Bh の 07h（リキャリブレート、6.3）の処理、INT 1Bh の 0Fh（リトラクト、6.3）の処理を行う。
   容量コードが 111b のユニットや、手順 3 で見つからなかったユニットにも行い、結果は見ない（Q17）。
   リキャリブレートとリトラクトの最後は組 A のパラメータ設定なので、初期化のあとのコントローラは組 A の設定になる（読み書きは組 A で行われる）。
5. AH は常に 00h（CF = 0）。

### 4.5 エラーの読み替え
根拠: NEC の SASI BIOS の解析[[46]](#ref-46)[[45]](#ref-45)[[58]](#ref-58)、UX-31 のコントローラのファームウェアの解析[[153]](#ref-153)、テクニカルデータブック[[51]](#ref-51)。

REQUEST SENSE のバイト 0 の bit5〜0 で引く。

| センス | 00h〜03h、05h〜0Fh | 04h | 10h | 11h | 12h | 13h | 14h | 15h | 16h | 17h | 18h | 19h | 1Ch | 1Eh | 1Fh | 21h | 23h | そのほか |
|---|---|---|---|---|---|---|---|---|---|---|---|---|---|---|---|---|---|---|
| AH | 40h | 60h | A0h | B0h | E0h | F0h | C0h | C8h | 40h | 70h | 08h | D0h | B8h | 88h | 50h | 38h | 30h | 40h |

- 08h は「訂正したデータエラー」で、成功の扱い（CF = 0）。

### 4.6 待ち時間
根拠: NEC の SASI BIOS の解析[[46]](#ref-46)[[45]](#ref-45)[[58]](#ref-58)。

- SASI バスの状態を待つループは、1 回の待ちあたり 65536 回程度の読み出しで時間切れ（AH = 90h）にする。
- 完了の割り込みの待ち（2.4 の手順 4）は、V30 8 MHz で約 10 秒を目安に時間切れにする。FORMAT DRIVE（04h。INT 1Bh の Dh で AH の bit7 = 1）だけは約 10 分にする
  （本物のドライブは全体のフォーマットに時間がかかる）。数え方は、0000:055Fh を読む回数でも、82h の読み出しの回数でも、タイマでもよい（タイマの状態は壊さない）。
  速い CPU では短くなってよい（Q24 と同じ考え）。時間切れのあとも、コントローラのリセットはしない（2.4 の手順 7、Q21）。止まったターゲットがバスを空けなければ、
  以後の呼び出しは選択の時間切れ（90h）で返り、INT 1Bh の 03h（初期化）で直る。
- 初期化の TEST UNIT READY の間の待ちは、V30 8 MHz で約 0.2〜0.5 秒を目安にする。元の BIOS は CPU の速さの種類で回数を増やす[[46]](#ref-46)が、
  この BIOS は見なくてよい（速い CPU では待ちが短くなるが、回数で補える。Q24）。実装はタイマを使ってもよい（その場合はタイマの状態を壊さない）。
- 正確な値は未確認（未解決 5）。実機のドライブ（UX-31 など）が立ち上がるのに十分な長さにする。

## 5. ブート（0015h）
根拠: NEC の SASI BIOS の解析[[46]](#ref-46)[[45]](#ref-45)[[58]](#ref-58)、テクニカルデータブック[[3]](#ref-3)。

- 0000:04B0h が自分のセグメントのときだけ動く。持ち主でなければ何もせず RETF。
- 入力: AL = 起動装置のコード（本体がメモリスイッチ SW5 の bit7〜4 から決める。0 なら 1 から 0Fh まで順に呼ばれる）。DS = 0。
- AL = 0Ah なら 80h、0Bh なら 81h について、0000:055Dh のそのビットが 1 なら、そのユニットから起動を試みる。それ以外の AL では何もせず戻る。
- 起動の手順:
  1. 0000:04ACh〜04AFh を退避する。
  2. BX = 0100h にして新センス（AH = 84h）を出す。返った BX が 0100h なら読み込み先を 1FE0:0000h、そうでなければ 1FC0:0000h にして、
     AH = 8Eh（モード設定、開放）を出す。
  3. ES = 読み込み先、BP = 0、BX = セクタ長 × 2、DX = 0 として、最大 8 回: INT 1Bh の 07h（リキャリブレート）→ INT 1Bh の 06h（読み出し、CHS 指定、
     CX = 0、DX = 0）。どちらかが CF = 1 ならやり直す。
  4. 読んだデータのオフセット 4〜7 が "IPL1" か確かめる。違えばあきらめる（やり直さない）。
  5. 一致すれば、0000:0584h（DISK_BOOT）= DA/UA、04ACh = BP（0）、04AEh = ES として、IPL を FAR CALL する。
     IPL に入るときのレジスタ: AL = DA/UA、ES:BP = IPL の先頭、BX = 読んだバイト数、DS = 0。IPL が戻ってきたら手順 3 に戻る
     （回数は 8 回から数え直す。毎回すぐ戻る IPL では繰り返し続けるが、元の BIOS と同じ振る舞い。Q22）。
  6. あきらめるとき: INT 1Bh の 0Eh（モード設定）と 0Fh（リトラクト）を出し、04ACh〜04AFh と DS を戻して RETF。ほかのレジスタは壊れていてよい（4.1。Q48）。
- ブートは 80h、81h だけ（本体が渡す AL が 0Ah、0Bh だけなので。不採用の付録 A の 4 台の案でも同じ）。

## 6. INT 1Bh（0018h）

### 6.1 入口と出口
根拠: テクニカルデータブック[[51]](#ref-51)[[52]](#ref-52)、NEC の SASI BIOS の解析[[46]](#ref-46)[[45]](#ref-45)[[58]](#ref-58)。

- 本体の INT 1Bh ハンドラは、STI、CLD のあと DS、SI、DI、ES、BP、DX、CX、BX、AX の順にスタックに積み、BP = SP、DS = 0 にして、
  AL の上位 4 ビットで 0000:04B0h の表を引き、0018h へ FAR JMP する。
- 0018h に入ったとき: [BP+0] = 呼び出し元の AX（[BP+0] = AL、[BP+1] = AH）、[BP+2] = BX、[BP+4] = CX、[BP+6] = DX、[BP+8] = BP、
  [BP+0Ah] = ES、[BP+0Ch] = DI、[BP+0Eh] = SI、[BP+10h] = DS、[BP+12h] = IP、[BP+14h] = CS、[BP+16h] = FLAGS。
  レジスタの AX、BX は壊れているので、入力はスタックから読む。
- 出口: 結果の AH を [BP+1] に、出力のレジスタを該当する欄に書く。AH ≥ 20h なら [BP+16h] の CF を 1、そうでなければ 0 にする。
  DMA のチャネル c をマスクし（15h に 04h + c。2.3）、AX、BX、CX、DX、BP、ES、DI、SI、DS を積んだ逆順に取り出して IRET する。

### 6.2 共通の決まり

- 機能は AH の下位 4 ビットで決まる。上位 4 ビットは修飾（bit7 = 新センス / 薄型 / ドライブ全体、bit6 = 未使用、bit5 = リトライなし、bit4 = 未使用）。
- ユニットは AL の bit0（0 = ユニット 0、1 = ユニット 1）。AL の bit7 は CHS 指定（1）かリニア指定（0）か。
  AL の bit1 は見ない（82h、83h は 80h、81h と同じになる）。0000:055Dh は見ない（ないユニットでもコマンドを出し、
  コントローラの答えで返す）。
- BIOS の中でリトライしない。リトライはコントローラに任せ、AH の bit5 が 1 なら制御バイトを C0h にする。
- 該当しない機能コードは、何もせず AH = 00h（CF = 0）で返す（テクニカルデータブック[[51]](#ref-51)の「コマンドに該当しないコードが指定された場合は
  正常終了する」に合わせる）。

### 6.3 機能
根拠: テクニカルデータブック[[51]](#ref-51)[[52]](#ref-52)、Undocumented 9801/9821[[1]](#ref-1)、NEC の SASI BIOS の解析[[46]](#ref-46)[[45]](#ref-45)[[58]](#ref-58)。

### 6.4 読み書きの手順（5h、6h、1h）
根拠: NEC の SASI BIOS の解析[[46]](#ref-46)[[45]](#ref-45)[[58]](#ref-58)、テクニカルデータブック[[51]](#ref-51)。

1. 0000:0481h のそのユニットのビットが 1 なら AH = 40h で終わる。
2. DMA を設定する: ES:BP から物理アドレス（ES × 16 + BP）を求め、64 KB の境界の検査（2.3）をし、アドレス、ページ、
   カウント（BX − 1）、モードを書いてマスクを外す。
3. アドレスを計算する（3.3）。ブロック数は、256 バイトのセクタなら BH、512 バイトなら BH ÷ 2（その結果が 0 なら 80h）。BX の下位 8 ビットは見ない。
   - BX = 0 は 65536 バイト（DMA のカウント FFFFh、ブロック数 0 = 256 ブロック、512 バイトなら 80h = 128 ブロック）になり、計算が合う。
   - BX がセクタ長より小さいと、ブロック数は 0（256 ブロック）か 80h になり、64 KB ぶんのコマンドが出る（DMA のカウントは BX − 1 のまま）。BX がセクタ長の倍数でないときも、端数は DMA のカウントにだけ効く。元の BIOS の振る舞いで、この BIOS も同じにする（呼び出し側の誤り）。
4. コントローラを選び、82h に C3h を書き、CDB を送り、完了を待ってステータスを読む（2.4）。
5. 結果が 08h（訂正したデータエラー）のとき（**6h の読み出しだけ**。5h と 1h は、AH の bit5 によらず AH = 08h のまま返す。Q19、Q44）:
   - AH の bit5 が 1（リトライなし）なら AH = B8h で終わる。
   - そうでなければ、センスのアドレスが有効（0586h の bit7）なら、そのアドレス + 1 から残りのブロックを READ（08h）で読み直す。最後まで読めたら AH = 08h。
     センスのアドレスが無効か、残りがブロックの途中なら AH = 40h。
   - 残りの求め方（Q20）: 8237 のチャネル c の現在のカウント（I/O 19h に書いてバイトポインタを戻し、チャネル c のカウントの I/O（c = 0 なら 03h。2.3）を下位、上位の順に読む）+ 1 が残りのバイト数。
     カウントが FFFFh（終わりまで送った）なら読み直さずに AH = 08h。DMA のアドレスは設定し直さず、続きから使う。
     読み直しでまた 08h が返ったら、同じ手順を繰り返す（残りは毎回減るので終わる）。センスのアドレスと DMA の残りが食い違っても確かめない（センスのアドレスを使う）。

## 7. 試験

- 実装側は、この文書の各節に対応する試験を用意する（SASI のターゲットのモック、8237、8259 の最小の模型の上で INT 1Bh を呼ぶ）。
  このリポジトリの `bios/test/`（IDE BIOS 用の試験の枠組み。NEC の ROM を含まない）を使ってよい。
- 調査側は、実機（UX21 と UX-31、または SASI エミュレータ）で、MS-DOS 6.20 と 5.00 の起動、FORMAT、読み書き、N88-BASIC(86) の
  DISK-BASIC の起動を確かめる。

## 付録 A: 4 台に広げる案（80h〜83h）— 不採用、検討の記録だけ残す

**不採用（2026-10-29、ユーザーの決定）**: SASI の容量を広げられれば（付録 C）、4 台は要らない。この BIOS は 80h、81h の 2 台だけを扱う。以下は検討の記録。


- 前提: 同じコントローラ（ターゲット ID 0）の LUN 0〜3 に 4 台がある（SASI エミュレータが LUN 2、3 にも応える）。
- 変更点:
  - ユニットを AL の bit1〜0 で決め、LUN 0〜3 にする。
  - 3 台目、4 台目の容量コードは I/O 82h にないので、決め打ちにするか、エミュレータに独自の命令を足して問い合わせる（決めていない）。
  - 0000:055Dh の bit2、bit3 を立てる。
  - パラメータ表のポインタと 0481h の閉鎖のビットは 2 台分しかない。3 台目、4 台目は、呼ばれるたびに容量コードから表を引くか、
    空いている作業域を使う（0481h の bit2、bit3 がほかで使われていないかは未確認）。
  - 作業域の候補（Undocumented 9801 のメモリの項[[1]](https://www.webtech.co.jp/company/doc/undocumented_mem/) で「未使用」とされる番地。2026-10-29 に調べた）: 045Fh（「未使用(?)」）、048Fh、05A7h、05B6h、05B9h〜05BFh（7 バイト）、05E4h。
    ほかの機種やソフトが後から使った例（05B7h、05B8h は Plug and Play 対応機が使う）があるので、使うなら最小限にする。
    UX にない装置の領域（0460h〜047Fh は PC-9801-55 などの SCSI、041Eh〜0443h と 049Ah〜04ABh は PC-9864、05C2h〜05C5h は GP-IB ボード）は、その装置を挿すと重なる。
- MS-DOS 3.3D と 5.00 の IO.SYS は 055Dh の bit0〜3 を全部調べて 4 台を登録する[[49]](#ref-49)。
- ブートは 80h、81h だけ（5）。

## 付録 B: DMA チャネルの選び方（0.14 版で採用）

**規則**: 0000:0484h の bit4 が 1 なら bit7〜6 のチャネル、0 ならチャネル 0（2.3）。

**理由**
- Undocumented 9801 のメモリの項[[1]](#ref-1) の 0000:0484h: bit7〜6 は「内蔵ハードディスクインターフェースの DMA チャネル」（00b はチャネル 0 か内蔵 HDD なし）、
  bit5 は「内蔵 SCSI あり」、bit4 は「内蔵 SASI あり」。RA21、RS、DA、DS、DX、GS、RL などに SASI 型の内蔵 HDD を実装したとき、本体（ITF）がセットする。
  同じ資料のSASI の項では、T、DA、DS、DX、CS、GS、RL（ノーマル）の SASI の内蔵型は、ディップスイッチ 3-3 でチャネル 0 / 1 を選べる。-07、-27 はチャネル 0 固定。
- 専用スロットの内蔵 SASI ユニット（純正の内蔵用増設ユニットや SASIHBA-SLOT）は、3-3 の設定でチャネル 1 につながることがある。この BIOS がそのユニットを扱うには、bit7〜6 に従う必要がある。
- C-bus の SASI ボード（-27、UX の P2 のユニット、SASIHBA-UX）は DRQ0 に固定でつながり、3-3 の切り替えを通らない。チャネル 0 でよい。
  専用スロットにつなぐ SASIHBA-SLOT は、純正の内蔵ユニットと同じく 3-3 の切り替えを通り、本体が bit4 を立てるので、bit7〜6 に従う。
- bit4 を条件にする理由:
  - 内蔵 SCSI があるとき（bit5 = 1）の bit7〜6 は SCSI のチャネルなので、SASI に使うと誤る。
  - bit4 が 1 になるのは、本体の専用スロットに SASI のユニットがあるとき。そのとき I/O 80h、82h はそのユニットのもので、C-bus の SASI ボードは同時に使えない。
    だから bit4 = 1 で bit7〜6 に従っても、C-bus の SASI ボードを誤らせない。
  - 0484h の bit7〜6 を使わない機種（RA2、RX2、RX21 など。メモリの項）や、本体が 0484h を作らない機種（UX、ES など）では、bit4 は 0 なのでチャネル 0 になる（UX、ES で 0484h が 0 であることは実機で未確認。8 章の 9）。

## 付録 C: 10 バイトのコマンドと SCSI のターゲット（任意、2026-10-29）

純正の UX-31（コントローラ DS300B-520）との互換を保ったまま、10 バイトのコマンド（READ CAPACITY 25h、READ 28h、WRITE 2Ah）に応えるターゲット
（SASI エミュレータ、変換番長、SCSI のターゲット）では容量の表を使わずに動く、という拡張。

**UX-31 のコントローラの振る舞い**（コントローラのファームウェアの解析による[[153]](#ref-153)）
- コマンドフェーズでは、命令コードによらず 6 バイトを受け取る（0Eh と C2h だけは続けてデータを受け取る、2.5）。
- 2.5 の表にない命令（25h、28h、2Ah を含む）は、6 バイトを受け取ったところでセンス 20h（不正な命令）にし、ステータスフェーズ（状態バイト 02h + LUN × 20h）に進む。
  つまり 10 バイトのうち 7 バイト目からは受け取られない。
- REQUEST SENSE で返すのは 4 バイト（2.5）。

**ホストの手順の決まり（この拡張を入れるときに必須）**
- **コマンドを 1 バイトずつ送る前に、フェーズを確かめる。** REQ = 1 を待ち、そのとき CXD = 1、IXO = 0、MSG = 0（コマンドフェーズ）なら 80h に書く。
  CXD = 1、IXO = 1（ステータスフェーズ）なら、残りのバイトを送らずにステータスの読み出し（2.4 の 5）へ進む。
  - 理由: ACK# は 80h への書き込みで回路が出す（2.4）。ステータスフェーズに入っているのに 80h に書くと、その ACK# で状態バイトを読まずに受け取ったことになり、手順が崩れる。
  - 2.4 の 2 の「CXD = 1、IXO = 0 になるのを待つ」を、そのまま 10 バイトに使うと、7 バイト目で永久に待つ。
- 調べる命令（READ CAPACITY）は、82h に C0h（INTE なし）のまま PIO で出す。INTE を立てると、ステータスフェーズの REQ で割り込みが入る（2.2）。
- データフェーズも、バイト数を決め打ちにせず、各バイトの前にフェーズを確かめる（REQUEST SENSE を 4 バイトより多く求めて、4 バイトでステータスに進む相手がいるため）。

**初期化での見分け方（ユニットごと）**
調べるユニットは、I/O 82h の容量コードによらず全部（2026-10-29 決定）。容量コードが「未接続」（111b）でも調べる。
SCSI のターゲットだけをつなぐ基板は容量コードを持たない（全部 111b と読める作りにする）ので、111b を飛ばすと何も見つからないため。

1. リセットのあと、ユニットを選択する。BSY が決まった時間のうちに 1 にならなければ（ターゲットがいない）、そのユニットは「なし」。
   この時間切れは、ユニットごとに起動を遅らせるので短くする: 82h の読み出し 8192 回程度（V30 8 MHz で約 10 ms）。
   調べるとき以外（読み書きなど）の選択は 4.6 のとおり（Q37）。
2. 最初の命令として READ CAPACITY（25h、LUN は 1 バイト目の bit7〜5）を出す。TEST UNIT READY は先に出さない
   （UX-31 のコントローラは表にない命令をドライブに触らずにすぐ断るが、TEST UNIT READY はドライブの状態を見るので、ドライブのない LUN で時間がかかるおそれがある。推測）。
   - 拡張センスで UNIT ATTENTION（センスキー 6h。SCSI のターゲットの電源投入直後）なら、2 回までやり直す。
   - 正常に 8 バイト（最終 LBA、ブロック長。どちらもビッグエンディアン）が返れば **10 バイト型**。C2h は出さない。
     ブロック長が 256 か 512 でなければ、そのユニットは使わない。ジオメトリは容量ごとに決める（下の「10 バイト型のジオメトリ」）。
   - CHECK CONDITION で、4 バイトの SASI のセンスが 20h（不正な命令）なら **6 バイト型**。容量コードが 111b ならユニットは「なし」、
     そうでなければ以後は本文どおり（容量コード、パラメータ表、C2h、TEST UNIT READY、6 バイトの READ / WRITE）。
   - 拡張センスで ILLEGAL REQUEST（その LUN がない、命令を受けない、など）なら「なし」。READ CAPACITY を受けない SCSI のターゲットは扱わない。
   - そのほかのエラーなら「なし」。
3. 結果（6 バイト型 / 10 バイト型、ID、LUN、ジオメトリの型）をユニットごとに覚える。覚える場所は 05E8h / 05ECh のポインタ（2.6 の「作業域」）。
   ポインタが ROM の中の、型と宛先ごとの表を指すようにし、表の「そのほか」の欄に 10 バイト型の印、宛先（ID 0 の LUN n か、ID n の LUN 0 か）、
   セクタ数などを置く。表の +04h には、その型で使えるシリンダ数の上限 − 1 を置き、実際のシリンダ数は 84h のたびに READ CAPACITY から求めてよい（Q34）。
   読み書き（6.4）、新センス（6.3 の 4h）はこれで分ける。
4. 見分けは 4.4 の手順 2（リセット）のあと、そのユニットの 4.4 の手順 3 の前に行う（ほかのユニットの手順 3 との前後は問わない。Q46）。INT 1Bh の 03h が出されるたびに調べ直す（Q35）。
   4.3 の手順 3 の 0E00h、0E01h は見分けの前に出されるので、10 バイト型と分かったユニットは、見分けたときに 0481h のそのビットを、ブロック長 512 なら 1（0E00h、0E01h を
   出したあとと同じ閉鎖の状態）、256 なら 0 にする（Q35。0.11 版で 512 を 1 に改めた。8 章の 7）。
5. 81h の先の候補（ID 0 の LUN 1）が 6 バイト型と分かり、容量コードが 111b でなければ、4.4 の手順 3 の TEST UNIT READY が最後まで成功しなくても、
   次の候補（ID 1 の LUN 0）は調べない（6 バイト型の宛先のまま、055Dh のビットは立てない）（Q41）。
6. 81h の次の候補（ID 1 の LUN 0）が READ CAPACITY に 4 バイトの SASI のセンス 20h（不正な命令）で答えたとき（ID 1 に 6 バイト型の SASI のコントローラがいる）は、
   そのユニットは「なし」とする。6 バイト型として扱うのは ID 0 のコントローラだけ（82h の容量コードは ID 0 のコントローラの 2 台の分なので、ID 1 には使えない）。
   81h は ID 0 の LUN 1 の 6 バイト型の宛先に戻し、容量コードが 111b なら 055Dh の bit1 は 0 のまま（Q49）。
- REQUEST SENSE の結果は、1 バイト目が 70h か 71h なら SCSI の拡張センス（センスキーは 3 バイト目の bit3〜0）、そうでなければ 4 バイトの SASI のセンスとして読む。
- REQUEST SENSE で求めるバイト数（CDB の 4 バイト目）: 6 バイト型のユニットは 4、10 バイト型のユニットと見分けの間は 18。0000:0586h〜0589h には
  先頭の 4 バイトを置き、残り（5 バイト目から）は読み捨てる。センスキー（3 バイト目）は先頭の 4 バイトの中にある（Q38。0.8 版で、スタックに読む形から改めた）。
- 拡張センスの AH への読み替え（センスキーで引く。Q39）:

  | センスキー | 0h | 1h | 2h | 3h | 4h | 5h | 6h | 7h | そのほか |
  |---|---|---|---|---|---|---|---|---|---|
  | 意味 | NO SENSE | RECOVERED ERROR | NOT READY | MEDIUM ERROR | HARDWARE ERROR | ILLEGAL REQUEST | UNIT ATTENTION | DATA PROTECT | |
  | AH | 40h | 00h | 60h | A0h | 40h | 38h | 60h | 70h | 40h |

  RECOVERED ERROR は成功（AH = 00h）として扱い、6.4 の手順 5 の読み直しはしない。

**10 バイト型での読み書き**
- リニア指定は DX:CX の 32 ビット、CHS 指定は作ったジオメトリで LBA に直す。READ(10) / WRITE(10) の LBA は 4 バイト、ブロック数は 2 バイト。
- ベリファイ（1h）は、82h の bit1 によらず READ(10) を、DMA のベリファイ転送（モード 40h）で出す（Q36）。
- 10 バイトの命令（READ CAPACITY、READ(10)、WRITE(10)）と、10 バイト型のユニットへの 6 バイトの命令（TEST UNIT READY、REQUEST SENSE）の制御バイトは、
  AH の bit5 によらず 00h（SCSI では制御バイトの bit7〜6 はベンダーごとの意味なので。Q43）。見分けの間（型がまだ分からないとき）に出す REQUEST SENSE も 00h。6 バイト型と分かったあとの命令は 2.5 のとおり bit5 に従う（Q45）。
- 新センス（84h）は BX = ブロック長、CX、DH、DL は作ったジオメトリを返す。

**ユニットとターゲットの ID / LUN の対応**（2026-10-29 決定）
SASI の流儀（ID 0 の LUN 0、1）と SCSI の流儀（ID ごとに LUN 0）の両方に合わせる。ユニットは 80h、81h の 2 台（4 台の案は不採用、付録 A）。

| ユニット | 先に調べる | 「なし」なら次に調べる |
|---|---|---|
| 80h | ID 0 の LUN 0 | — |
| 81h | ID 0 の LUN 1 | ID 1 の LUN 0 |

- 純正の UX-31 と変換番長の SASI モードは ID 0 の LUN で、SCSI のエミュレータは ID ごとに 1 台で見つかる。
- 見つかった ID と LUN をユニットごとに作業域に覚え、以後の選択（2.4 の 1）と CDB の LUN（1 バイト目の bit7〜5）に使う。
- 81h で 2 つの候補がどちらも「なし」のときは、宛先を先の候補（ID 0 の LUN 1）とし、6 バイト型として扱う（055Dh のビットは立てない）。
  6.2 のとおり、INT 1Bh は 055Dh を見ずに命令を出すので、そのとき 81h への命令は ID 0 の LUN 1 へ行き、コントローラの答え（センス）で返る。
- ブートは 80h、81h の両方から（5）。
- 選択のとき 80h に書くのは、ターゲットの ID のビットとホストの ID のビット（ID 7 = 80h）の両方。6 バイト型でも同じ（UX-31 のコントローラが余分なビットを気にしないかは未確認。気にするなら 6 バイト型ではターゲットのビットだけにする）。

**10 バイト型のジオメトリ**（2026-10-29 決定。容量の段ごとに決める、EXIDE5 の IDE 拡張モードと同じ考え方）
N = 最終 LBA + 1（ブロック数）。シリンダ数 = N ÷（ヘッド数 × セクタ数）の切り捨てで、65535 で頭打ち（超える分は使わない）。

| ブロック長 | 容量 | ヘッド × セクタ | センス（04h）と新センス（84h）の AH | 理由 |
|---|---|---|---|---|
| 256 | N ≤ 615 × 8 × 33（約 40 MB） | 3.1 の表の型（40、20、10、5 MB）のうち、N ≥（その型のシリンダ数 − 1）× ヘッド数 × 33 となる最大のもの。ヘッド数と AH はその型、シリンダ数は上の計算（型のシリンダ数で頭打ち） | その型の値 | 6 バイト型と同じ見え方にし、既存の SASI のイメージ（1 シリンダ少ない 614 × 8 × 33 のものを含む）をそのまま使う |
| 256 | それより大きい | 使わない（「なし」と同じ。055Dh のビットを立てない） | — | ブロック長 256 は 40 MB まで（0.13 版、ユーザーの決定）。40 MB を超える容量はブロック長 512 で作る |
| 512 | N ≤ 65535 × 8 × 17（4351 MiB） | 8 × 17 | 0Fh / 0Fh | NEC の内蔵 IDE BIOS と同じ。C-bus IDE-CF ボードの BIOS と同じ |
| 512 | それより大きい | 16 × 63（最大 32255 MiB） | 0Fh / 0Fh | EXIDE5 の IDE 拡張モード、C-bus IDE-CF ボードの BIOS と同じ |

- 512 バイトの規則を C-bus IDE-CF ボード（CBIDE）の BIOS と揃える（上の表の右の欄）ので、同じ中身のイメージや CF を、SASIBIOS で使う SASI のディスク（UXSE など）、C-bus IDE-CF ボード（CBIDE）、EXIDE5 を入れた PC-9821 の内蔵 IDE の間で行き来させられる。
- 256 バイトで約 40 MB 以下の型を選んだユニットの厚型 / 薄型（0Eh / 8Eh）は 3.4 と同じ。それ以外のユニットでは 0Eh / 8Eh は表を替えずに正常終了する。
  ブロック長 512 のユニットの 0481h の閉鎖と開放は 3.4 のとおり（0Eh で閉鎖、8Eh で開放。0.11 版）。
- 256 バイトで、どの型の条件（N ≥（その型のシリンダ数 − 1）× ヘッド数 × 33）にも当たらないユニット（5 MB の型より小さい）は使わない（「なし」と同じ。055Dh のビットを立てない）。
- ブロック長 256 の上限は N = 615 × 8 × 33 = 162,360 ブロック（41,564,160 バイト）。エミュレータの標準の 40 MB の HDI（615 シリンダ）も、1 シリンダ少ない
  614 シリンダのイメージ（変換番長など）も、この中に入る。これを超えるブロック長 256 のユニットは、上の表のとおり使わない（BIOS はターゲットのブロック長を変えない）。
- 10 バイト型のユニットでの、読み書き以外の機能（6.3 の表の置き換え）:
  - 0h（シーク）、7h（リキャリブレート）、Fh（リトラクト）、Dh（フォーマット。AH の bit7 によらない）、Bh（代替トラックの割り当て）は、ターゲットに命令を出さず、AH = 00h で返す。
  - 8h（代替トラックの指定）は 6.3 と同じ（ディスクには触らず、そのユニットのジオメトリで LBA を求めて ES:BP に書く）。LBA が 21 ビットを超えるときは、下位 21 ビットを書く（Q42）。
  - 4h（センス）は 6.3 と同じく TEST UNIT READY を出し、エラーならその AH。正常なら AH = 上の表の「センス（04h）と新センス（84h）の AH」の左の値。84h（新センス）のときは、BX = ブロック長、CX = シリンダ数 − 1、DH = ヘッド数、DL = セクタ数を上の表の規則で返し、AH = 同じ欄の右の値。容量は、初期化のときに得た値でも、READ CAPACITY を出し直した値でもよい。
- AH = 0Fh は「80 MB 以上」の値（C-bus IDE-CF ボードの BIOS と同じ）。DISK-BASIC 6.1 / 6.2 はこの値のドライブを扱えない（6.3 の汎用の道だけ）。
- OS ごとの容量の上限（この付録のジオメトリで。OS の側の制約で、BIOS は気にしなくてよい。実機では未確認）:

  | OS | 使えるディスク全体 | 決めているもの |
  |---|---|---|
  | N88-BASIC(86) 6.1 / 6.2 | 40 MB（614 × 8 × 33 × 256 バイト） | FORMAT.HD が 3.1 の表の型しか扱わない。AH = 0Fh と 512 バイトのドライブは受け付けない |
  | N88-BASIC(86) 6.3 | 約 2,281 MB（32,768 × 8 × 17 × 512 バイト）。1 つの領域は 120 MB まで、同時に使えるのは 1 つ | FORMAT.HD がシリンダ数を 16 ビットの整数で持つ |
  | MS-DOS 5.00 | ディスクの先頭の 65,536 トラック（シリンダ × ヘッド数）まで: 8 × 17 で 544 MiB、16 × 63 で 2016 MiB | 区画の位置の計算で、トラック番号の上位 16 ビットを捨てる |
  | MS-DOS 6.20 | 8 × 17 で 4351 MiB、16 × 63 で 32255 MiB | 区画表のシリンダが 16 ビット（65535 まで） |
  | FreeDOS(98) | MS-DOS 6.20 と同じ | 同上 |

  MS-DOS 5.00 / 6.20 は 256 バイトの物理セクタも扱うが、大きな容量には 512 バイトを勧める（DISK-BASIC 6.3 も 512 バイトを扱う）。

## 付録 E: 対象機種の例（2026-11-01）

1.1 の条件に当たる機種の例。出どころは主にテクニカルデータブック HARDWARE 1993[[3]](#ref-3)の第 2 部 第 9 章「固定ディスク」（229〜232 ページ）で、
内蔵 IDE の機種は UNDOCUMENTED 9801/9821 のオンライン版のIDE の項[[1]](#ref-1)も使った（どちらも 1993〜1997 年ごろまでの機種）。
SASIBIOS を実際に置けるか（拡張 ROM の焼き直しなど、1.2）は機種ごとに別の話で、ここでは扱わない。

**1. SASI の固定ディスクを標準で内蔵した機種**（[3] 229 ページ。8086 の F3、M3 を除く）
- PC-9801VM4、VX4、VX41、UX41、RA5、RX4、LS5、EX4、ES5、LX4、LX5、LX5C、RA51、RS51、RX51
- PC-9801T model W5、S5、F5、DX5、DX/U5、DS5、DS/U5、DA5、DA/U5
- PC-98XL model 4、PC-98XL^2、PC-98RL model 5、51（ノーマルモードで使うとき）

  内蔵の 1 台だけを扱う。

**2. 内蔵用増設の SASI 固定ディスクを付けられる機種**（[3] 231〜232 ページ。このオプションは PC-9801-27 の機能を含み、付けたあとは外部に増設用の固定ディスクを 1 台つなげる）

| 本体 | 内蔵用増設の固定ディスク |
|---|---|

**3. PC-9801-27 で SASI の固定ディスクをつなぐ機種**（[3] 231 ページ「上記以外の機種では、PC-9801-27 で外部に SASI の固定ディスクを 2 台つなげる。ラップトップ型は I/O 拡張ユニットなどが要る」）
- 1、2 にない V30 以上の機種。例: PC-9801VM0、VM2、VM21、VX0、VX2、VX21。
- SCSI の固定ディスクを標準で内蔵した PC-9801DA7、DA/U7、T model W7、F71、FA5、FA/U5、FA7、FA/U7、FS5、FS/U5、FX5、FX/U5、FS7、FS/U7（[3] 230 ページ）。
  これらは内蔵 IDE を持たず、[3] 230 ページの「PC-9801-27 を使えない」一覧にもない。

**対象外**
- **PC-9821 の全機種。** 一覧にある PC-9821 は、どれも内蔵 IDE を持つ（IDE の項[[1]](#ref-1)）か、SCSI を内蔵して PC-9801-27 を使えない
  （PC-9821 model S2、PC-9821Ce model S2。[3] 230 ページ）。[推測] 一覧より後の PC-9821（Xc、Xv20、Ra、Rv、Cr、Nr など）も内蔵 IDE を持つ [/推測]
- 内蔵 IDE の PC-9801 と 98NOTE（IDE の項[[1]](#ref-1)の一覧）: PC-9801NS、UR、P、NL/R、NL/A、NS/L、US、PC-H98T、98NOTE（PC-9801N、NV、NL を除く）、
  PC-9801BA、BX、BA2、BS2、BX2、BX3、BX4。
  [3] 230〜231 ページでも、NS、NC、US、NA、NS/R、NX/C、BA、BX などは、内蔵の固定ディスクを付けると PC-9801-27 を使えない。

**資料どうしの食い違い**
- PC-9801UR/20 は [3] 229 ページでは「SASI 準拠の固定ディスクを標準で内蔵」の一覧にあるが、IDE の項[[1]](#ref-1)では 2.5 インチの IDE を内蔵した機種で、
  drachen6jp 氏の分類でも内蔵 IDE の第 0 世代。[推測] [3] の「SASI 準拠」は BIOS の呼び方（DA/UA 80h）が SASI と同じという意味で、ハードウェアは IDE [/推測]
  この仕様では対象外とする。

**わかっていないこと**
- PC-98XA（model 1、11、3、31）、PC-98GS、PC-H98 の各型は、ノーマルモードの扱いと拡張 ROM の呼び出し方（1.1 の条件 3）が未確認なので、例に入れていない。
- 98NOTE の PC-9801N、NV、NL（内蔵 IDE がない）と、PC-98DO、DO+（V30、V33A）が条件 3 に当たるかは未確認。
- 一覧（1993〜1997 年ごろ）にない機種。
